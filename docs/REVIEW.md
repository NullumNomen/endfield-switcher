## 存储策略的边界

3 份是每个平台保留的快照数，不是全盘 3 个文件，也不是固定容量配额。每份快照引用当时的平台差异，共享内容去重。8 GiB 是一次适配的两平台差异总量上限，以及单次切换的目标暂存量上限；仓库总占用仍取决于所保留版本的差异。Git 重打包与暂存还会产生短期峰值。

存在未完成事务时暂不裁剪历史和缓存，优先保证可以恢复。用户反复中断或长期不完成恢复时，空间不会保证立即归还。恢复完成后自动维护或执行 compact。外部自行创建的 Git refs、备份、手动复制的程序目录不由本工具清理。

历史裁剪会重建保留提交的父链，提交编号和提交日期可能变化；文件树内容保持不变。不向外提供旧快照编号永久有效的保证。

## 仍需现场验证

1. 独立新机器上的全流程联网初始化、下一次真实游戏大版本更新、Steam／Epic 商店实际启动和支付入口。此前已验证过现有安装双向切换和 Steam 登录，本轮不把模拟测试等同于新机器端到端验证。
2. 真正断电、NTFS／硬盘故障和系统强制终止后的恢复。本工具有事务记录、文件同步与校验，但不能保证硬件故障下零数据损失。
3. 任意外部程序在检查之后立即改写文件的竞态无法完全消除；切换期间仍应关闭游戏及官方启动器，不要手动启动更新或直接操作本地 Git 仓库。
4. 本次未进行完整第三方依赖漏洞数据库审计；源代码审查和 clippy 通过不构成没有漏洞或永不崩溃的保证。
